# 01 - 工作空间管理模块

## 1.1 模块概述

工作空间管理模块负责创建、查询、更新和删除工种工作空间。每个工作空间对应一个工种（如前端开发、后端开发、产品经理等），工作空间内包含该工种所需的全部数据文件，包括题库、面试记录、JD模板等。系统预设 7 个工种工作空间，首次使用时自动初始化。

## 1.2 模块目标
- 提供统一的工种工作空间管理机制
- 支持多工种并行管理
- 首次使用时自动初始化预设工作空间
- 管理工作空间配置信息（考察维度、权重、目标职级）

## 1.3 功能列表

| 功能编号 | 功能名称 | 功能描述 | 优先级 |
|---------|---------|---------|--------|
| WS-001 | 获取工作空间列表 | 查询所有已创建的工作空间 | P0 |
| WS-002 | 获取工作空间详情 | 查看指定工作空间的完整配置 | P0 |
| WS-003 | 创建工作空间 | 创建新工种的工作空间及目录结构 | P0 |
| WS-004 | 更新工作空间 | 修改工作空间配置信息 | P0 |
| WS-005 | 删除工作空间 | 删除工作空间及其所有数据 | P1 |
| WS-006 | 工作空间校验 | 校验工作空间目录结构完整性 | P1 |
| WS-007 | 工作空间统计 | 统计工作空间内题目数量、面试数量等 | P2 |
| WS-008 | 预设初始化 | 首次使用时自动初始化7个预设工作空间 | P0 |

## 1.4 功能详细说明

### WS-001 获取工作空间列表

**输入**：可选筛选条件：工种分类（技术研发/产品设计）

**处理逻辑**：
1. 扫描 `{workspaceRoot}/` 根目录
2. 遍历每个子目录，读取 `workspace.md` 文件
3. 使用 `gray-matter` 解析 YAML Front Matter 获取工作空间元数据
4. 统计各工作空间的题目数量和面试记录数量
5. 返回工作空间列表

### WS-002 获取工作空间详情

**输入**：jobRole（必填）：工种代码

**处理逻辑**：
1. 验证工作空间目录是否存在
2. 读取 `workspace.md` 文件
3. 使用 `gray-matter` 解析 YAML Front Matter 和 Markdown 正文
4. 统计题库数量（按难度等级分组）
5. 统计面试记录数量

### WS-003 创建工作空间

**输入**：
```typescript
interface CreateWorkspaceInput {
  job_role: string
  workspace_name: string
  category: '技术研发' | '产品设计'
  target_levels: string[]
  evaluation_dimensions: Dimension[]
}
```

**处理逻辑**：
1. 校验工种代码格式（小写字母+下划线）
2. 检查工作空间是否已存在
3. 创建目录结构（question-bank/L1-L5、interviews、templates）
4. 生成 `workspace.md` 配置文件

### WS-004 更新工作空间

**输入**：jobRole + updates 对象

**处理逻辑**：读取现有文件 → 更新 YAML Front Matter → 原子写入保存

### WS-005 删除工作空间

**输入**：jobRole + force（是否强制删除）

**处理逻辑**：检查面试记录 → 如有记录且未强制删除则抛出确认异常 → 删除整个目录

### WS-006 工作空间校验

**处理逻辑**：检查必需目录 → 检查 workspace.md 格式 → 验证 YAML Front Matter 字段完整性 → 检查权重总和

### WS-007 工作空间统计

**处理逻辑**：遍历 question-bank 按难度统计 → 遍历 interviews 按状态统计 → 遍历 templates 统计

### WS-008 预设初始化

**处理逻辑**：首次加载时检查工作空间目录 → 如为空则自动创建 7 个预设工作空间 → 写入默认配置

**预设工作空间**：

| 工种代码 | 工种名称 | 分类 | 默认考察维度 |
|---------|---------|------|-------------|
| frontend_dev | 前端开发工程师 | 技术研发 | 基础知识(0.2)、实践能力(0.25)、系统设计(0.2)、项目经验(0.2)、沟通协作(0.15) |
| backend_dev | 后端开发工程师 | 技术研发 | 同上 |
| algorithm_eng | 算法工程师 | 技术研发 | 同上 |
| test_eng | 测试工程师 | 技术研发 | 同上 |
| data_dev | 数据开发工程师 | 技术研发 | 同上 |
| product_mgr | 产品经理 | 产品设计 | 同上 |
| ui_designer | UI设计师 | 产品设计 | 同上 |

## 1.5 数据文件规范

**workspace.md 格式**：
```markdown
---
job_role: frontend_dev
workspace_name: 前端开发工程师
category: 技术研发
target_levels: [P3, P4, P5, P6, P7]
evaluation_dimensions:
  - name: 基础知识
    weight: 0.2
    description: HTML/CSS/JavaScript基础
  - name: 实践能力
    weight: 0.25
    description: 框架使用与项目实践
  - name: 系统设计
    weight: 0.2
    description: 架构设计与技术选型
  - name: 项目经验
    weight: 0.2
    description: 实际项目经验与贡献
  - name: 沟通协作
    weight: 0.15
    description: 沟通表达与团队协作
created_at: 2026-04-17T00:00:00.000Z
updated_at: 2026-04-17T00:00:00.000Z
---

# 前端开发工程师 - 工作空间
（工种描述、各职级能力要求、考察维度说明）
```

## 1.6 非功能需求

- 获取列表响应时间：< 1秒，创建工作空间：< 2秒，单文件读取：< 100ms
- 删除操作需强制确认参数
- 创建失败自动回滚
- 工作空间数据完全存储在本地，支持离线查看，可直接纳入 Git 版本控制
