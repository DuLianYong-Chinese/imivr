## 1. 工作空间管理模块

### 1.1 模块概述

工作空间管理模块负责创建、查询、更新和删除工种工作空间。每个工作空间对应一个工种（如前端开发、后端开发、产品经理等），工作空间内包含该工种所需的全部数据文件，包括题库、面试记录、模板等。模块通过 Node.js 文件系统操作 Markdown 文件，支持插件化扩展。

### 1.2 模块目标
- 提供统一的工种工作空间管理机制
- 支持多工种并行管理
- 自动初始化工作空间目录结构
- 管理工作空间配置信息
- 支持从插件自动创建工作空间

### 1.3 功能列表

| 功能编号 | 功能名称 | 功能描述 | 优先级 |
|---------|---------|---------|--------|
| WS-001 | 获取工作空间列表 | 查询所有已创建的工作空间 | P0 |
| WS-002 | 获取工作空间详情 | 查看指定工作空间的完整配置 | P0 |
| WS-003 | 创建工作空间 | 创建新工种的工作空间及目录结构 | P0 |
| WS-004 | 更新工作空间 | 修改工作空间配置信息 | P0 |
| WS-005 | 删除工作空间 | 删除工作空间及其所有数据 | P1 |
| WS-006 | 工作空间校验 | 校验工作空间目录结构完整性 | P1 |
| WS-007 | 工作空间统计 | 统计工作空间内题目数量、面试数量等 | P2 |
| WS-008 | 从插件创建工作空间 | 根据插件配置自动初始化工作空间 | P1 |

### 1.4 功能详细说明

#### WS-001 获取工作空间列表

**输入**：可选筛选条件：工种分类（技术研发/产品设计）

**处理逻辑**：
1. 使用 `fs.readdir()` 扫描 `workspaces/` 根目录
2. 遍历每个子目录，读取 `workspace.md` 文件
3. 使用 `gray-matter` 解析 YAML Front Matter 获取工作空间元数据
4. 统计各工作空间的题目数量和面试记录数量
5. 返回工作空间列表

```typescript
async function listWorkspaces(options?: { category?: string }): Promise<WorkspaceInfo[]> {
  const workspacesDir = path.resolve('workspaces');
  const entries = await fs.readdir(workspacesDir, { withFileTypes: true });
  const workspaces = [];
  for (const entry of entries.filter(e => e.isDirectory())) {
    const workspacePath = path.join(workspacesDir, entry.name);
    const { metadata } = await readMarkdownFile(path.join(workspacePath, 'workspace.md'));
    if (options?.category && metadata.category !== options.category) continue;
    workspaces.push({
      job_role: metadata.job_role, workspace_name: metadata.workspace_name,
      category: metadata.category, target_levels: metadata.target_levels,
      created_at: metadata.created_at, question_count: await countQuestions(workspacePath),
      interview_count: await countInterviews(workspacePath)
    });
  }
  return workspaces;
}
```

#### WS-002 获取工作空间详情

**输入**：jobRole（必填）：工种代码

**处理逻辑**：
1. 验证工作空间目录是否存在
2. 读取 `workspace.md` 文件
3. 使用 `gray-matter` 解析 YAML Front Matter 和 Markdown 正文
4. 统计题库数量（按难度等级分组）
5. 统计面试记录数量

```typescript
async function getWorkspaceDetail(jobRole: string): Promise<WorkspaceDetail> {
  const workspacePath = path.resolve('workspaces', jobRole);
  if (!(await exists(workspacePath))) throw new WorkspaceNotFoundError(jobRole);
  const { metadata, body } = await readMarkdownFile(path.join(workspacePath, 'workspace.md'));
  return { ...metadata, content: body, question_stats: await countQuestionsByDifficulty(workspacePath), interview_count: await countInterviews(workspacePath) };
}
```

#### WS-003 创建工作空间

**输入**：
```typescript
interface CreateWorkspaceInput {
  job_role: string; workspace_name: string; category: '技术研发' | '产品设计';
  target_levels: string[]; evaluation_dimensions: Dimension[];
}
```

**处理逻辑**：
1. 校验工种代码格式（小写字母+下划线）
2. 检查工作空间是否已存在
3. 创建目录结构（question-bank/L1-L5、interviews、templates）
4. 生成 `workspace.md` 配置文件
5. 如果存在对应插件，从插件加载默认模板

#### WS-004 更新工作空间

**输入**：jobRole + updates 对象

**处理逻辑**：读取现有文件 → 更新 YAML Front Matter → 原子写入保存

#### WS-005 删除工作空间

**输入**：jobRole + force（是否强制删除）

**处理逻辑**：检查面试记录 → 如有记录且未强制删除则抛出确认异常 → 删除整个目录

#### WS-006 工作空间校验

**处理逻辑**：检查必需目录 → 检查 workspace.md 格式 → 验证 YAML Front Matter 字段完整性 → 检查权重总和

#### WS-007 工作空间统计

**处理逻辑**：遍历 question-bank 按难度统计 → 遍历 interviews 按状态统计 → 遍历 templates 统计

#### WS-008 从插件创建工作空间

**处理逻辑**：加载插件 → 读取 plugin.json → 从插件 rules/dimensions.json 获取配置 → 复制默认模板 → 调用 WS-003

### 1.5 数据文件规范

**workspace.md 格式**：
```markdown
---
workspace_name: 前端开发工程师
job_role: frontend_dev
category: 技术研发
target_levels: [P3, P4, P5, P6, P7]
evaluation_dimensions:
  - name: 基础语法
    weight: 0.2
    description: HTML/CSS/JavaScript基础
created_at: 2026-04-17
---

# 前端开发工程师 - 工作空间
（详细说明）
```

### 1.6 非功能需求

- 获取列表响应时间：< 1秒，创建工作空间：< 2秒，单文件读取：< 100ms
- 删除操作需强制确认参数，操作日志记录到本地
- 创建失败自动回滚，支持工作空间导入/导出
- 工作空间数据完全存储在本地，支持离线查看，可直接纳入 Git 版本控制

## 2. 简历管理模块

### 2.1 模块概述

简历管理模块负责候选人简历的上传、解析、存储和查询。支持多种格式的简历文件（PDF、Word、图片），通过 OCR 和 AI 技术将简历内容结构化提取，并以 Markdown 文件形式存储在工作空间中。

### 2.2 模块目标
- 支持多种格式的简历文件上传
- 自动解析简历内容并结构化
- 提供简历信息的查看和编辑功能
- 与面试流程无缝集成

### 2.3 功能列表

| 功能编号 | 功能名称 | 功能描述 | 优先级 |
|---------|---------|---------|--------|
| RES-001 | 上传简历 | 上传简历文件到指定面试记录 | P0 |
| RES-002 | 简历解析 | AI 解析简历内容并结构化 | P0 |
| RES-003 | 查看简历 | 查看已解析的简历信息 | P0 |
| RES-004 | 编辑简历 | 手动修正解析结果 | P1 |
| RES-005 | 删除简历 | 删除简历文件及解析结果 | P1 |
| RES-006 | 简历列表 | 查看面试中的简历列表 | P1 |
| RES-007 | 简历搜索 | 按关键词搜索简历 | P2 |

### 2.4 功能详细说明

#### RES-001 上传简历

**输入**：interviewId + resumeFile

**处理逻辑**：验证面试目录 → 校验文件格式和大小 → 保存文件 → 触发解析流程

**支持格式**：PDF、DOC、DOCX、PNG、JPG、JPEG、WEBP，≤10MB

#### RES-002 简历解析

**处理逻辑**：根据文件类型选择解析方式（PDF→pdf-parse，DOC→mammoth，图片→tesseract.js）→ 调用 AI 结构化解析（从插件加载 Prompt）→ 生成 resume.md

**AI 解析 Prompt**：
```
请分析以下简历内容，提取以下信息：
1. 基本信息（姓名、联系方式、邮箱）
2. 教育背景（学校、专业、学历、时间）
3. 工作经历（公司、职位、时间、主要职责）
4. 技术技能（编程语言、框架、工具）
5. 项目经验（项目名称、技术栈、个人贡献）
请以 JSON 格式返回结构化数据。
```

#### RES-003 查看简历 / RES-004 编辑简历 / RES-005 删除简历

使用 `gray-matter` 解析/更新 resume.md 文件，支持原子写入。

#### RES-006 简历列表 / RES-007 简历搜索

遍历工作空间下的面试目录，读取 resume.md 元数据，支持按解析状态筛选和关键词搜索。

### 2.5 数据文件规范

**resume.md 格式**：
```markdown
---
candidate_name: 张三
contact: 13800138000
email: zhangsan@example.com
work_years: 2
education:
  - school: 某某大学
    major: 计算机科学与技术
    degree: 本科
    start_date: "2018-09"
    end_date: "2022-06"
skills: [JavaScript, Vue, React, TypeScript, Node.js]
parsed_at: 2026-04-17T10:30:00Z

# 候选人简历 - 张三
（详细内容）
```

### 2.6 非功能需求

- 上传响应时间：< 3秒，解析：< 5秒，查看：< 1秒，单文件读取：< 100ms
- 文件类型白名单校验，AI 调用仅发送必要文本，敏感信息可脱敏
- 解析失败支持手动修正，原始文件保留
- 简历文件完全存储在本地，支持离线查看

### 5.4 功能详细说明

#### QG-001 生成问题清单

**输入**：
```typescript

  interviewId: string; jobRole: string; questionCount: number;
  difficultyDistribution: Record<string, number>;
  useQuestionBank?: boolean; aiGenerateRatio?: number;
}
```

**处理逻辑**：
1. 读取候选人简历和HC配置

6. 生成 questions.md 保存

#### QG-002 查看 / QG-003 调整 / QG-004 重新生成

支持查看、增删改问题，重新生成时备份原文件。

#### QG-005 问题推荐 / QG-006 问题预览

分析当前清单覆盖情况，识别缺失维度，推荐补充题目。支持预览问题及期望答案。

## 7. 评分管理模块

### 7.1 模块概述

评分管理模块负责面试官对候选人答题情况的评分。支持按题目评分、按考察维度汇总评分、提供评分参考标准。模块通过 Node.js 文件系统操作 Markdown 文件，使用 `gray-matter` 解析和写入评分数据。

### 7.2 模块目标
- 提供标准化的评分流程
- 支持按题目逐一评分
- 提供评分标准参考
- 按考察维度汇总评分
- 支持评分修改和备注

### 7.3 功能列表

| 功能编号 | 功能名称 | 功能描述 | 优先级 |
|---------|---------|---------|--------|
| SM-001 | 获取评分列表 | 获取所有题目的评分状态 | P0 |
| SM-002 | 获取题目评分 | 获取单道题目的评分详情 | P0 |
| SM-003 | 提交评分 | 提交单道题目的评分 | P0 |
| SM-004 | 批量评分 | 批量提交多道题目评分 | P1 |
| SM-005 | 修改评分 | 修改已提交的评分 | P0 |
| SM-006 | 获取维度评分 | 按考察维度汇总评分 | P0 |
| SM-007 | 评分统计 | 获取评分统计信息 | P1 |
| SM-008 | 评分参考 | 获取评分标准参考 | P1 |

### 7.4 功能详细说明

#### SM-001 获取评分列表

读取 answers.md 和 questions.md，合并返回题目和评分状态。

#### SM-003 提交评分

**输入**：
```typescript
interface SubmitScoreInput {
  interviewId: string; questionId: string; score: number;
  scoreRemark?: string; passed: boolean;
}
```

**处理逻辑**：验证评分范围（0-10整数）→ 读取 answers.md → 更新评分 → 记录评分时间 → 原子写入

#### SM-004 批量评分

校验所有评分 → 批量更新 → 返回成功/失败统计

#### SM-006 获取维度评分

**计算公式**：综合评分 = Σ(各题得分 × 题目权重 × 考察维度权重) / Σ(题目权重 × 考察维度权重) × 10

按维度分组 → 计算平均分 → 计算加权得分 → 返回汇总

#### SM-007 评分统计

计算：总题目数、已评分数、通过数、未通过数、平均分、最高分、最低分。

#### SM-008 评分参考

从题库中查找对应题目文件，读取 score_criteria 和 expected_answer。

### 7.5 非功能需求

- 获取列表：< 2秒，提交评分：< 1秒，批量评分：< 3秒，单文件读取：< 100ms
- 评分修改日志记录，操作审计追踪
- 支持评分修改和批量操作，提供评分标准参考
- 评分数据完全存储在本地，支持离线评分

## 8. 等级评定模块

### 8.1 模块概述

等级评定模块根据候选人的面试评分结果，结合各考察维度权重和难度系数，综合评定候选人的职级（P3-P7）。支持纯计算模式和 AI 辅助模式两种评定方式。

### 8.2 模块目标
- 基于评分结果自动评定职级
- 提供详细的维度分析
- 给出优势与不足评价
- 提供录用建议
- 支持 AI 辅助评定和手动调整

### 8.3 功能列表

| 功能编号 | 功能名称 | 功能描述 | 优先级 |
|---------|---------|---------|--------|
| LA-001 | 执行等级评定 | 根据评分结果评定职级 | P0 |
| LA-002 | 获取评定结果 | 获取等级评定详情 | P0 |
| LA-003 | 重新评定 | 重新执行等级评定 | P1 |
| LA-004 | 手动调整 | 手动调整评定结果 | P1 |
| LA-005 | 评定参考 | 获取评定标准参考 | P2 |

### 8.4 功能详细说明

#### LA-001 执行等级评定

**输入**：interviewId + assessmentMethod（auto/manual）+ useAI（可选）

**处理逻辑**：
1. 读取 answers.md 获取评分数据
2. 从 workspace.md 获取考察维度权重
3. 计算各维度加权得分和综合得分
4. 根据得分区间确定职级
5. 分析优势与不足，生成录用建议
6. 创建 assessment.md 保存

**职级评定标准**：
| 职级 | 名称 | 综合得分区间 | 说明 |
|------|------|-------------|------|
| P3 | 初级 | 0-4.5 | 基础能力，需要培养 |
| P4 | 初级 | 4.5-5.5 | 具备基础工作能力 |
| P5 | 中级 | 5.5-7.0 | 独立工作能力 |
| P6 | 高级 | 7.0-8.5 | 技术骨干，能解决复杂问题 |
| P7 | 专家 | 8.5-10 | 领域专家，能引领技术方向 |

**AI 辅助评定**：从插件加载 Prompt，调用 AI 生成优势/不足/建议。AI 失败时自动降级为纯计算模式。

#### LA-002 获取评定结果 / LA-003 重新评定 / LA-004 手动调整

读取 assessment.md，支持重新评定（备份原文件），支持手动调整并记录原因。

#### LA-005 评定参考

返回各职级的评分区间和要求说明。

### 8.5 数据文件规范

**存储位置**：`workspaces/{job_role}/interviews/{date}-{name}/assessment.md`

```markdown
---
interview_id: int-20260417-001
candidate_name: 张三
recommended_level: P6
comprehensive_score: 7.5
strengths: [基础扎实, 框架原理理解深入, 项目经验丰富]
weaknesses: [工程化经验不足, 性能优化实战较少, 微前端了解不够]
hiring_recommendation: 建议录用
assessed_at: 2026-04-17T11:30:00Z

# 等级评定结果 - 张三

## 基本信息
| 项目 | 内容 |
|------|------|
| 推荐职级 | P6 |
| 综合得分 | 7.5/10 |

## 维度得分分析
| 维度 | 权重 | 得分 | 等级 |
|------|------|------|------|
| 基础语法 | 20% | 8.5 | 优秀 |
| 框架原理 | 25% | 7.5 | 良好 |
```

### 8.6 非功能需求

- 评定响应时间：< 10秒（AI）/ < 2秒（纯计算），获取结果：< 2秒
- AI 失败时自动降级为纯计算模式
- 评定结果完全存储在本地，评定标准存储在插件目录
