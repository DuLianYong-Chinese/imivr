# 我是面试官 - 项目构建方案

## 1. 背景与目标

将「我是面试官」从纯前端 Vite 项目改造为可本地安装的 npm CLI 工具，支持命令行启动、安装引导、配置管理等能力，类似 OpenClaw 的使用体验。

**核心目标**：用户通过 `npm install -g imivr-bobfintech` 全局安装后，即可使用 `imivr` 命令完成所有操作。

## 2. 参考架构分析

以 OpenClaw 为参考，分析其 CLI 架构并提取适用于 imivr 的设计模式。

### 2.1 OpenClaw 架构特点

| 特性 | OpenClaw 实现 | imivr 适配方案 |
|------|-------------|---------------|
| 全局安装 | `npm install -g openclaw` | `npm install -g imivr-bobfintech` |
| CLI 入口 | `package.json` bin 字段 → CLI 脚本 | 同 |
| 安装引导 | `openclaw onboard` 交互式向导 | `imivr init` |
| 启动服务 | `openclaw gateway --port 18789` | `imivr start --port 5173` |
| 配置管理 | `~/.openclaw/openclaw.json` | `~/.imivr/imivr.json` |
| 工作空间 | `~/.openclaw/workspace/` | `{workspaceRoot}/`（用户自定义） |
| 健康检查 | `openclaw doctor` | `imivr doctor` |
| 卸载 | `openclaw uninstall` | `imivr uninstall` |

### 2.2 可借鉴的设计模式

- `bin` 字段配置 CLI 入口
- commander 做子命令分组
- 交互式向导用 @clack/prompts
- 配置文件放在用户目录 `~/.imivr/`
- `start` 命令同时启动 API 服务 + 静态文件服务
- `doctor` 命令做环境检查

### 2.3 不适用 imivr 的部分

OpenClaw 的 Gateway/Channel/Agent 管理、Docker 沙箱、浏览器自动化、定时任务、多通道对接（飞书/微信等）等功能，imivr 作为单机面试辅助工具不需要。

## 3. 技术选型

| 层面 | 技术 | 选型理由 |
|------|------|---------|
| CLI 框架 | Commander.js | 轻量、流行、与 OpenClaw 一致 |
| 服务端 | Express 5 | 简单够用，不需要 Koa 的 async 中间件 |
| 构建工具 | tsup | 基于 esbuild，构建速度快 |
| 交互式向导 | @clack/prompts | 比 inquirer 更现代美观 |
| 配置存储 | JSON 文件 | `~/.imivr/imivr.json` |
| 前端 | Vite + React | 现有技术栈不变 |

## 4. 架构设计

### 4.1 CLI + Web 服务架构

```
用户执行 imivr start
  → CLI 进程启动
  → 启动 Express 服务器（提供 /api/fs/* 等 API）
  → serve Vite build 产物（dist/web/ 目录）
  → 自动打开浏览器 http://localhost:5173
```

### 4.2 构建流程

```
1. tsup 构建 CLI 代码 → dist/cli/
2. vite build 构建前端 → dist/web/
3. CLI 启动时 serve dist/web/ 作为静态文件
```

### 4.3 开发模式

```
pnpm dev
  → vite dev server（前端热更新，端口 5173）
  → 同时启动 API 服务（端口 3001，代理文件系统操作）
```

## 5. CLI 命令设计

```
imivr                          # 默认启动（等同于 imivr start）
imivr --version                # 查看版本
imivr --help                   # 查看帮助

imivr start                    # 启动服务（默认端口 5173）
imivr start --port 3000        # 指定端口启动

imivr init                     # 安装引导向导
imivr doctor                   # 健康检查
imivr uninstall                # 卸载（清理配置、工作空间数据）
imivr config                   # 查看配置
imivr config set <key> <value> # 设置配置项
imivr config get <key>         # 获取配置项
```

## 6. 实施阶段

### 阶段 1：项目结构重组
- 创建 CLI 入口文件 `src/cli/index.ts`
- 配置 `package.json` 的 `bin` 字段
- 分离前端构建产物与 CLI 服务端代码

### 阶段 2：CLI 命令框架
- 使用 Commander.js 搭建命令解析框架
- 实现 `imivr --version` / `imivr --help`
- 实现 `imivr start [options]` 启动 Web 服务
- 实现 `imivr init` 安装引导向导
- 实现 `imivr doctor` 健康检查
- 实现 `imivr uninstall` 卸载命令

### 阶段 3：服务端集成
- 将 Vite 插件 `fs.mjs` 改造为独立的 Express 服务端
- 实现文件系统 API（读写配置、工作空间文件）
- CLI 启动时同时启动 API 服务 + 静态文件服务
- 生产模式下 serve Vite build 产物

### 阶段 4：安装引导（Onboarding）
- 交互式 CLI 向导（选择工作目录、配置 AI 模型）
- 首次运行自动检测并引导配置
- 预设工作空间初始化

### 阶段 5：配置管理
- 统一配置文件 `~/.imivr/imivr.json`
- `imivr config get/set` 命令
- 配置迁移/升级机制

### 阶段 6：构建与发布
- 配置 tsup 构建 CLI
- 配置 `.npmignore` 排除源码
- 配置 `package.json` 的 `files` 字段
- `npm publish` 发布到 npm registry

## 7. npm 发布流程

### 7.1 发布前准备

**1) 配置 `.npmignore`**

npm publish 默认会参考 `.gitignore`，但 `.gitignore` 中排除了 `dist/`（构建产物），会导致发布时缺少必要文件。需要创建独立的 `.npmignore`：

```
node_modules/
src/
public/
electron/
plugins/
vite/
vite.config.ts
tsconfig.json
tsconfig.node.json
tsup.config.ts
.eslintrc.cjs
index.html
.imivr/
demo/
workspaces/
*.log
.trae/
```

**2) 配置 `package.json` 发布字段**

```json
{
  "name": "imivr-bobfintech",
  "version": "1.0.8",
  "main": "dist/cli/index.js",
  "bin": {
    "imivr": "dist/cli/index.js"
  },
  "files": [
    "dist/cli",
    "dist/web"
  ],
  "scripts": {
    "build": "pnpm build:cli && pnpm build:web",
    "build:cli": "tsup src/cli/index.ts --format esm --out-dir dist/cli --clean",
    "build:web": "tsc && vite build --outDir dist/web",
    "prepublishOnly": "pnpm build"
  }
}
```

关键字段说明：
- `bin.imivr`：全局安装后 `imivr` 命令指向 `dist/cli/index.js`
- `files`：只发布 `dist/cli` 和 `dist/web` 两个目录
- `prepublishOnly`：发布前自动执行 `pnpm build`，确保产物最新

**3) 验证打包内容**

```bash
pnpm pack --dry-run
```

预期输出：
```
📦 imivr-bobfintech@1.0.8
Tarball Contents
dist/cli/index.js
dist/web/assets/index-xxx.css
dist/web/assets/index-xxx.js
dist/web/imivr-logo.svg
dist/web/index.html
package.json
README.md
```

### 7.2 发布步骤

**1) 登录 npm（首次需要）**

```bash
npm login
```

输入 npm 账号、密码和邮箱。如未注册，先去 [npmjs.com](https://www.npmjs.com) 注册。

**2) 构建**

```bash
pnpm build
```

**3) 发布**

```bash
npm publish
```

如果 npm 账号开启了双因素认证（2FA），推荐使用 Automation Token 免去每次输入验证码（见下方 7.3 节）。

### 7.3 免 2FA 验证码配置（推荐）

每次发布都输入 OTP 验证码很麻烦，可以通过创建 **Automation Token** 一劳永逸：

**1) 创建 Automation Token**

1. 登录 [npmjs.com](https://www.npmjs.com) → 头像 → **Access Tokens**
2. 点击 **Generate New Token** → 选择 **Automation** 类型
3. 复制生成的 token（格式：`npm_xxxxxxxxxxxx`）

**2) 配置本地认证**

```bash
npm set //registry.npmjs.org/:_authToken=npm_xxxxxxxxxxxx
```

**3) 之后发布无需 OTP**

```bash
npm publish
```

Automation 类型的 token 可以绕过 2FA，适合本地开发和 CI/CD 场景。

### 7.4 发布中遇到的问题与解决

| 问题 | 错误信息 | 解决方案 |
|------|---------|---------|
| 2FA 认证 | `E403 - Two-factor authentication required` | 临时方案：`npm publish --otp=验证码`；永久方案：配置 Automation Token |
| 包名冲突 | `Package name too similar to existing package immer` | 改名为 `imivr-bobfintech` |
| 版本覆盖 | `Cannot publish over previously published versions` | 升级版本号（如 1.0.0 → 1.0.1） |
| Express 5 路由 | `Missing parameter name at index 1: *` | `app.get('*')` 改为 `app.use()` |

### 7.5 发布后验证

```bash
# 全局安装
npm install -g imivr-bobfintech

# 验证命令
imivr --version
imivr --help
imivr doctor
imivr start
```

### 7.6 本地调试（免发布）

开发阶段不需要每次发布到 npm，使用 `npm link` 将本地项目链接到全局：

```bash
# 一次性设置
npm link

# 日常调试
pnpm build:cli    # 只构建 CLI（快）
imivr start       # 直接测试

# 取消链接
npm unlink -g imivr-bobfintech
```

## 8. 实施结果

### 8.1 新增文件

| 文件 | 说明 |
|------|------|
| `src/cli/index.ts` | CLI 入口，Commander.js 命令注册 |
| `src/cli/server.ts` | Express 服务端，文件系统 API + 静态文件 |
| `src/cli/init.ts` | 安装引导向导 |
| `src/cli/doctor.ts` | 健康检查 |
| `src/cli/uninstall.ts` | 卸载命令 |
| `src/cli/config.ts` | 配置管理 |
| `tsup.config.ts` | tsup 构建配置 |

### 8.2 修改文件

| 文件 | 变更 |
|------|------|
| `package.json` | name → imivr-bobfintech, 添加 bin/files/main 字段, 新增 build:cli/build:web 脚本 |

### 8.3 验证结果

- `imivr --version` ✅ 输出版本号
- `imivr --help` ✅ 显示完整帮助
- `imivr doctor` ✅ 健康检查正常
- `imivr start --port 3099` ✅ Express 服务启动成功
- `GET /api/fs/config` ✅ API 返回配置数据

### 8.4 关键决策

1. CLI 框架选 Commander.js（轻量、流行、与 OpenClaw 一致）
2. 服务端选 Express（简单够用，不需要 Koa 的 async 中间件）
3. 构建工具选 tsup（基于 esbuild，构建速度快）
4. 交互式向导选 @clack/prompts（比 inquirer 更现代美观）
5. 配置文件放 `~/.imivr/imivr.json`（与 OpenClaw 的 `~/.openclaw/` 模式一致）
6. 端口冲突时自动重试（EADDRINUSE 自动查找可用端口）
